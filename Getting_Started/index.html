    Getting Started

    0: Brief Project Overview

    This project uses Godot and Kotlin. Godot is the game engine, and Kotlin is the language we are programming in. To program in Kotlin, we will be using the JVM-plugin for Godot. This page will provide resources to help you easily learn what you need to start working on this project.

    1: Tutorials

    Before working on the actual project, start by following these tutorials.

    The following tutorials are in the recommended order to follow before starting work on this project

    A: GD-Quest

    GD-Quest is a strong starting point for someone who has never programmed. It teaches variables, conditions, loops, functions, and other fundamentals through interactive exercises. The examples use GDScript, not Kotlin, but the programming concepts transfer.

    B: Intro to Godot

    You may follow this Youtube tutorial series, or navigate through these docs. The docs and tutorial series will likely include GD-Script programming. This is fine, you will learn Kotlin later. If you’ve used Godot before you may skip this step

    C: Learn Kotlin

    Kotlin Koans is a series of exercises to get you familiar with the Kotlin syntax and some idioms. Each exercise is created as a failing unit test, and your job is to make it pass. Don’t skip this unless you’ve used Kotlin before.

    D: Godot JVM

    Read the Godot JVM documentation. Now that you’ve learned how to program in Kotlin, and navigate Godot, the concepts should feel familiar here.

    2: Environment Setup

    You’ve likely already downloaded Godot, assuming you’ve followed the tutorials listed above. You very likely have not downloaded the Godot JVM plugin though.

    We will be using the community edition of the IntelliJ IDEA.

    Setup Instructions:

    1. Start by downloading the IDE linked above.
    2. Once it has been downloaded, navigate to the Plugins within the IDE. Search for “Godot Kotlin/JVM”. The plugin is published by “Utopia-Rise”.
      • Install the plugin to your IDE.
    3. Now search for “GitHub” in the plugins.
      • If this plugin isn’t installed already, please install it.

    3: GitHub

    Create an account on GitHub. Share your account user name with Thomas, and he will add you as a contributor to the project.

    4: Clone Repository

    Navigate to your IntelliJ IDE.  You will likely see an option to clone a repository, click this option.  

    Then you will be prompted for a link, now navigate to the GitHub repository, copy the link, and paste it into IntelliJ.

    The branch should now be loading, it may take a bit for it to build. You will probably need to link your GitHub account to the IDE.

    5: Start a Task

    On the GitHub, navigate to the Issues section.  You will see multiple tasks that you can pick up. You will see a labels section, click the label “good first issue”

    Find an issue with that label. Now you should assign the issue to yourself, and create a branch for you work on.  When creating a branch make sure you follow this naming scheme:

    “{item type}/scar-{issue#}-brief-title”

    Make sure you don’t have any special characters, only letters, numbers and “-” dashes.

    In the example below it results to: “issue/scar-1-create-initial-project-structure”

    There are different types of work items in this project, the most common are:

    • Standalone
      • A single unit of work linked to nothing else.  Worked on by one person.
      • Branches start with “issue/”
    • Story
      • A broad feature that is written from the perspective of a user/player.
      • Contains multiple tasks linked to it.
      • Branches start with “story/”
    • Task
      • A work item linked to a feature.
      • Branches start with “task/”
    • Bug
      • Something is broken or not working as intended and needs to be fixed.
      • Branches start with “bug/” 
    • Tech-Debt
      • A previous approach to an implementation was poor, or doesn’t follow good practice, and it needs to get fixed.
      • Branches start with “techdebt/"
    • Spike
      • Something needs to be investigated before work can be started.
      • Branches start with “spike/“.
